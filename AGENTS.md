# OpenWrtVPN

- Перед изменениями читать README.md, docs/development.md и применимые более локальные AGENTS.md. Если есть игнорируемый `local/AGENTS.md`, прочитать его перед работами на личном роутере владельца: там адреса, расположение приватного восстановления и локальные ограничения.
- Общие исходники: `router-reinstall-kit/files/`; публичная установка: `install.sh`; чистые настройки: `defaults/`. Персональный install-on-router.sh и приватные данные в рабочей копии не являются публичным установщиком.
- Существенные изменения после проверки оформлять коммитами и отправлять в origin. Перед разработкой крупной фичи создавать отдельную feature-ветку и вести коммиты/push в ней. Сливать ее в основную ветку только после отладки, тестирования и явного одобрения пользователя; завершение тестов само по себе не является разрешением на merge. Основная ветка сейчас main (под «мастером» понимать основную ветку, не переименовывать ее без запроса). Коммитить только относящиеся к задаче изменения, не включать чужие правки и приватные файлы.
- Не публиковать подписки с токенами, узлы/UUID, config.json рабочего подключения, кэш, персональные правила, архивы, логи и ключи. Перед публикацией проверять staged-файлы и `node tests/test-publication.js`. Не обходить .gitignore через add -f.
- Модуль модема opt-in: `INSTALL_MODEM=0` по умолчанию, runtime property `openwrtvpn.main.modem_enabled`. При 0 не должно быть модемных зависимостей, запусков и доступных CGI-действий. Не запускать изменяющие AT/USB-команды ради тестов.
- Обновление подписок меняет только кэш и идет через VPN, не пересобирает исправное соединение. Исключение — явный `bootstrap` при остановленном VPN. Проверки/обновления cron при выключенном VPN не выходят в сеть.
- Активный узел определять по локальному Clash API sing-box, не по логам фоновых проб. Сохранять `vpn-toggle prepare` в init для marked WAN bypass.
- LAN/WAN-адреса, SSH, существующие интерфейсы/зоны и штатный UI не менять. Новый веб-сервис привязывать только к LAN. Не прошивать и не сбрасывать работающий роутер.
- Проверки: `sh tests/run.sh` с jq/Node.js; для интерфейса — браузер на 320/390 px. Установку тестировать в изолированном стенде, не на работающем пользовательском устройстве. Различать unit/sandbox проверки и реальные сетевые/аппаратные испытания.
