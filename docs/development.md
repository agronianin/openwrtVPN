# Устройство проекта

Панель и CLI используют произвольные профили и [общий каталог](profiles.md). `vpn-profiles` использует библиотечный режим существующего импортера и генератора. Старый BLACK/WHITE CLI обслуживает подключения без управляемого профиля. Frontend `profiles.js`/`profiles.css` не использует фреймворки; CGI возвращает типизированный JSON с ошибками и свежим снимком.

`install.sh` — публичная установка с чистыми `defaults/`, копирует только явно перечисленные файлы. Игнорируемые архивы и `router-reinstall-kit/install-on-router.sh` в личной рабочей копии — отдельное персональное восстановление, не часть публичного пакета.

`vpn-subscriptions-update` читает BLACK/WHITE manifests, обходит зеркала до первого успеха, разбирает VLESS/hy2, дедуплицирует узлы и обновляет кэш. `update/refresh` не пересобирают конфигурацию. `bootstrap` только при остановленном VPN явно загружает начальные данные напрямую. `rebuild` собирает config.json, проверяет его и перезапускает работающий sing-box. Кэш/ключи/URLs не коммитить.

`SUBSCRIPTION_FETCH_MODE` в vpn-settings.conf задает транспорт: `vpn` (default), `direct`, `vpn-first`. Последний после ошибки curl через SOCKS делает прямую попытку того же URL. `fetch_direct` отключает прокси окружения/.curlrc, привязывается к реальному uplink из main-маршрута с WAN-mark и не меняет firewall. HTTP(S) обновления при OFF не выполняются, кроме явного bootstrap. Fallback относится к ошибке загрузки, а не к успешно скачанному неподдерживаемому формату: тот по-прежнему отклоняется парсером и запускает проверку следующего зеркала.

VLESS `flow` берется только из URI: отсутствие или пустое значение не включает Vision автоматически. SNI и flow независимы; наличие REALITY/SNI не означает необходимость `xtls-rprx-vision`.

`vpnctl` предоставляет пользовательские команды. `vpn-toggle` работает с procd и маршрутизацией. Init вызывает `vpn-toggle prepare`, чтобы помеченные соединения шли через WAN в обход TUN. LAN определяется через netifd, подключенные сети — через ip. GL.iNet `route_policy` обрабатывается при наличии.

Для managed-профилей `vpn-health-check auto` делегирует `vpn-connection auto`; legacy-путь сохранен только для старых неуправляемых конфигов. Новый контроллер использует cron и краткоживущий worker под flock, не новый постоянный демон. Проверка идет через принудительный VPN SOCKS; результат хранится в `/tmp/vpn-connection/last-check.json`. Настройки в `profiles/connection-settings.json`, job/progress в `/tmp/vpn-connection/job.json`. Подбор использует неизменяемый снимок кэша и реальные loaded-узлы, тестирует tier-ы через существующий `vpn-node-tests` по 60 (четыре параллельных HTTPS-теста), не модифицируя рабочий процесс во время поиска.

Перед переключением повторно проверяются активный профиль, SHA каталога/конфига, выбор API и версия настроек. Изменение отменяет поиск. Уже загруженный кандидат переключается native selector с `interrupt_exist_connections:false`, затем повторно проверяется. Новый кандидат при allow_reload собирает только outbounds поверх текущего config: route/DNS/inbounds не подменяются сохранёнными, но не применёнными правилами профиля. После `sing-box check` сохраняется rollback, выполняется один restart и ожидание готовности API до 15 секунд, затем проверка выбранного узла; отказ возвращает прежнюю конфигурацию. OFF-marker от vpn-toggle исключает повторное включение VPN при откате. Ручной/подобранный default сохраняется в config без рестарта; loaded-titles применяется только при совпадении полного SHA конфига.

`vpn-auto-update` читает период на каждом cron tick и обновляет кэш без применения. Плановое обновление переключается на общий каталог после активации управляемого профиля. При OFF фоновых сетевых действий нет. `sing-box-update` — opt-in обновление официального бинарника с SHA256/проверкой config, может рестартовать VPN. Архитектуры arm64/amd64/armv6/armv7; другие — SING_BOX_ARCH или ручная установка.

Панель — shell CGI + JS/CSS, отдельный LAN uhttpd, не заменяет LuCI. Новая установка использует системный пароль root, не хранит копию пароля. Настройки UCI `openwrtvpn.main`: `lan_interface`, `web_port`, `web_auth`, `modem_enabled`, `modem_apn`. После изменения привязки/модуля — restart панели. Периоды через веб применяются без рестарта VPN.

`.rules` сортируются по именам, формат документирован рядом с исходниками. Общедоступные defaults ограничены примерами; личные rules и compiled `.srs` локальны.
