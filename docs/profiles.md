# Произвольные профили

Данные устройства: `/etc/sing-box/profiles/catalog.json` (version 1). Здесь общий список подписок `{id,name,urls}` и профилей `{id,name,subscriptions,nodes,rules,final,preference}`. Списки профиля упорядочены. `preference`: `ru`, `non-ru`, `any`; `final`: `direct`, `vpn-out`. Подписка может участвовать в нескольких профилях. Узлы, явно добавленные в профиль, участвуют даже без включения всей подписки. Неиспользуемые источники сохраняются в каталоге, но не загружаются в активный config.json.

В интерфейсе подписка и ручная группа — два способа собрать узлы в одну группу. Подписка загружает их по зеркалам, ручная группа хранится локально. Добавление одного URI создаёт ручную группу с одним узлом. В списках узлов показывается имя группы. Профиль может включать группу целиком или ссылаться на отдельные узлы по их тегам.

Профиль, группа, правило и узел сохраняются отдельными кнопками. Несохранённые правки в других карточках остаются черновиками. При переименовании сохраняются ID профиля и группы, ID файла правила и тег узла. Пользовательские имена узлов хранятся в `nodeNames` каталога, а имя правила — в комментарии первой строки `# profile-name: Имя`. Обновление подписки сохраняет имя узла, пока его параметры дают тот же стабильный тег.

Порядок групп задаётся в профиле. Порядок отдельных узлов можно задать в карточке группы (поле **Приоритет узлов внутри группы**). Автовыбор сначала проверяет эти узлы по очереди, затем остальные узлы группы по предпочтению страны и задержке. После исчерпания группы проверяется следующая. Сохранение порядка само по себе не переключает текущий VPN.

При первом открытии панель создаёт каталог с примерами BLACK и WHITE без подписок. Источники добавляются вручную в разделе **Группы узлов**, затем назначаются профилю. Существующий каталог загружается как есть.

Кэш: `profiles/cache/<source-id>.*`. Теги узлов содержат хеш параметров подключения, поэтому перестановка строк в подписке не меняет идентификаторы. Если провайдер удалил явно выбранный узел, активация профиля сообщает об отсутствующем узле вместо подстановки другого по номеру. Country preference основано на названиях из подписок и является предпочтением, а не гарантией геолокации.

Последний выбранный ID: `profiles/active`, признак нового управления: `profiles/managed`. При OFF профиль запоминается для включения аппаратным переключателем, но сервис остановлен и панель показывает OFF. После удаления этого профиля при выключенном VPN нужно выбрать другой. Активация собирает конфигурацию: сначала `sing-box check`, затем замена и запуск; при ошибке запуска восстанавливаются предыдущие config и состояние выбора. Нативный selector `vpn-out` переключает загруженные узлы без рестарта. Повторная активация профиля выбирает первый узел; для измеренного оптимального выбора нажмите «Автовыбор узла».

На первом экране **Статус** кнопка **Применить профиль** повторно применяет сохранённый профиль после подтверждения, с возможным кратким разрывом и сбросом ручного выбора. **Обновить состояние** только читает данные. **Проверить подключение** запускает два HTTPS-запроса через фактический текущий выход и сохраняет результат с временем, ресурсом и узлом. Устаревший результат другого подключения явно помечается. **Автовыбор узла** запускает конечный изолированный поиск, а не постоянный режим. Панель показывает этап, прогресс и завершение/ошибку; перезагрузка страницы не теряет выполняющуюся операцию. Во время поиска можно выключить VPN, тогда переключение отменяется. Подробные подсказки описывают нюансы кнопок.

## Автовосстановление

Это отдельная настройка во вкладке **Статус**, по умолчанию выключена. Настройки сохраняются в `/etc/sing-box/profiles/connection-settings.json`: `enabled`, `interval_minutes` (1–1440), `failures` (2–10), `target`, `refresh_on_failure`, `allow_reload`. Сохранение действует со следующего минутного cron tick, без применения профиля или перезапуска VPN.

- Каждая проверка — два HTTPS-запроса через SOCKS текущего VPN. 2/2 — доступен; 1/2 — нестабильно, без замены узла. При 0/2 повторяются пары с паузой 5 секунд до заданного числа отказов. Изменение узла/профиля во время измерения отменяет его.
- После подтверждения отказа проверяется `https://ya.ru` напрямую, с привязкой к физическому uplink. Если direct тоже недоступен, текущий узел не меняется. Это консервативная проверка: недоступность самого ya.ru также отложит восстановление.
- Поиск использует только источники/узлы профиля. Приоритет подписки выше предпочтения страны; внутри первого рабочего уровня выбирается минимальная средняя HTTPS-задержка среди узлов с 2/2. Это не тест максимальной скорости. Кандидаты проверяются по 60, четыре параллельно, без остановки основного VPN. Для больших каталогов поиск может занять несколько минут; прогресс показывает проверенную долю, не точное оставшееся время.
- Нет подходящего кандидата — прежний выход сохраняется. Если включено `refresh_on_failure`, после неудачного обхода обновляются источники профиля и поиск повторяется. Способ загрузки берется из общего `SUBSCRIPTION_FETCH_MODE`; частичная ошибка не удаляет прежний кэш.
- Загруженный кандидат переключается через selector без рестарта и повторно проверяется. Для нового узла нужен один краткий перезапуск только после успешного изолированного теста и при `allow_reload=true`. При false поиск ограничен уже загруженными узлами. Отказ применения возвращает прежний конфиг/выбор. Правила, DNS и inbounds берутся из работающего конфига, а не из ещё не применённых правок профиля.
- Между автоматическими поисками минимум 10 минут. Разовая кнопка не требует включать автовосстановление. Ручной выбор остается фиксированным, но при включенном автовосстановлении подтверждённый отказ разрешает его заменить. Для безусловной ручной фиксации отключите автовосстановление.

Выбранный default сохраняется без рестарта. Старый `profile-auto` при первом поиске фиксируется на фактическом текущем узле; новые сборки не содержат постоянных URLTest. Обновление подписок по-прежнему не меняет исправное подключение. OFF запрещает сетевые проверки/подбор. `/tmp/vpn-connection/{last-check.json,job.json}` переживает обновление страницы, но не перезагрузку роутера; настройки сохраняются постоянно.

Обновления выполняются отдельным процессом cron: `profiles/update-request`, `profiles/update-job.json`, `/tmp/vpn-auto-update.log`. Панель не ожидает долгую загрузку в CGI. В «Периоды автоматизации» задается `SUBSCRIPTION_FETCH_MODE`: `vpn` (только SOCKS VPN, default), `direct` (только реальный uplink), `vpn-first` (после ошибки загрузки через VPN одна прямая попытка того же URL). Способ применяется при следующей операции без перезапуска VPN; начатая загрузка не перенаправляется посередине. При отключении VPN оставшиеся обновления и direct-повтор отменяются; bootstrap — отдельная явная команда для OFF. Direct влияет только на загрузку, не на правила или клиентский трафик. Провайдер подписки при direct видит обычный внешний IP. Ошибка источника не удаляет старый кэш. Снимок панели читается без долгой блокировки обновлением, запись каталога атомарна с SHA256-проверкой редакции. Для правил такая же защита отдельным revision файла. Большие каталоги отображаются с поиском и ограничением числа строк.

Правила хранятся в `rule-packs/available`, выбираются/упорядочиваются профилем. Их сохранение не применяет их к текущему соединению: повторно выберите профиль. Прямой обход локальных подсетей добавляется первым, даже если соответствующий набор не отмечен. Предыдущая редакция правила хранится в `.rules.previous`; удалить используемое правило нельзя.

Команды:

```sh
vpn-profiles snapshot                 # приватный JSON, содержит адреса подписок
vpn-profiles save REVISION < data.json # атомарно заменить каталог, без рестарта
vpn-profiles check PROFILE_ID         # проверить сборку без применения
vpn-profiles activate PROFILE_ID      # применить/включить профиль
vpn-profiles activate off             # выключить, запомнив последний профиль
vpn-profiles queue-update all         # очередь загрузки через работающий VPN
vpn-profiles update all               # синхронная загрузка для CLI/cron
vpn-profiles import-cache SOURCE_ID /tmp/subscription.txt # локальный файл в существующий источник, без рестарта
vpn-profiles bootstrap PROFILE_ID     # явно разрешенная начальная прямая загрузка, только при VPN off
vpn-profiles node auto
vpn-profiles node NODE_TAG
vpn-profiles test NODE_TAG            # отдельный временный процесс; основной не переключается
vpn-connection start find             # разовый подбор, JSON задания сразу; затем status
vpn-connection start check            # только проверка фактического выхода
vpn-connection status                 # настройки, последнее измерение, ход задания
```

Тест узла измеряет время HTTPS-запроса, не ICMP-пинг и не пропускную способность. Временный процесс слушает только loopback, завершается после теста. При включенном VPN его outbound имеет WAN-mark для обхода TUN. Новые зависимости/демоны не нужны.

`import-cache` принимает текстовую/base64 подписку до 16 MiB, сохраняет URL источника и не применяет данные к текущему соединению. Это позволяет скачать подписку через VPN другого устройства, передать файл по SSH и обновить существующий источник без временной замены его адреса. При неверном формате прежний кэш остается на месте. SOURCE_ID можно посмотреть в разделе «Группы узлов». Передача файла на роутер сама по себе не загружает его узлы в активный профиль.

## Проверка узлов

В **Узлы** выберите подписку/поиск, ресурс и **Быстрый тест**. Проверяются первые 60 подходящих узлов, по четыре одновременно. На каждый — два HTTPS-запроса с таймаутом 6 секунд, результат обновляется по мере выполнения. Для 60 узлов сетевой бюджет около трех минут плюс запуск и обработка; на перегруженном роутере время может быть больше. Рабочий VPN не переключается и не перезапускается.

- **2/2**: ресурс доступен в обеих попытках. **1/2**: нестабильно. **0/2**: ресурс недоступен через этот узел сейчас.
- **HTTPS, мс** — среднее время успешного запроса с DNS, установлением туннеля и TLS. Это не ICMP ping; `time_connect` до локального SOCKS не используется как задержка удаленного узла.
- Проверяются сертификат HTTPS и точный ожидаемый HTTP-код. Редирект, 403, ошибка DNS/TLS и таймаут не считаются успехом. Ответ 403 может означать ограничение конкретного сайта, а не сломанный туннель.
- **Ресурсы проверки**: Google, YouTube и Cloudflare с ожидаемым 204; можно добавлять/редактировать/удалять свои HTTPS-адреса и ожидаемый код 200–299. Сохранение действует сразу, не меняет VPN. Выбирайте небольшой стабильный URL без авторизации. Обычная страница с кодом 200 менее показательна: она может оказаться заглушкой. Успех YouTube generate_204 не доказывает доступность видеопотоков или всей географически ограниченной функциональности.
- **Тест скорости** отдельно подтверждается: после HTTPS-проверок последовательно скачивает по 2 MiB через узлы с 2/2. Максимум 120 MiB на 60 узлов, до 6 секунд на скачивание. Источник — `speed.cloudflare.com`, не direct-домен `mirror.yandex.ru`. Скорость в Мбит/с — короткий однопоточный замер с накладными расходами, а не гарантированный максимум канала. Неполное скачивание/ошибка выводится отдельно, не превращается в фиктивную скорость.

Все запросы теста используют `socks5h` отдельного loopback-процесса sing-box с явной привязкой inbound → проверяемый outbound. Direct-резерва в тестовой конфигурации нет; WAN-mark предотвращает повторное попадание тестовых соединений в основной TUN. TLS проверяется curl без `-k`, пользовательский `.curlrc` не читается. Основной selector не трогается. Результат характеризует узел из кэша и выбранный ресурс, не всю маршрутизацию Wi-Fi-клиентов. Страна/город в строке взяты из названия подписки, не из независимой геопроверки.

Если кэш обновился после открытия панели, устаревшие теги не подменяются узлами с похожими названиями: тест возвращает ошибку. Нажмите обновление состояния и повторите выбор. Автоматический полный обход соблюдает заданный интервал и после частичной ошибки, а не повторяется каждую минуту; занятая блокировка не считается выполненной попыткой. Ручное обновление остается доступным отдельно.

CLI: `/usr/bin/vpn-node-tests targets`, `targets-save REV` (JSON-массив на stdin), `start` (stdin: `{"tags":["NODE_TAG"],"target":"youtube","speed":false}`), `status JOB_ID`. Настройки: `/etc/sing-box/profiles/test-targets.json`; фоновые результаты и диагностика: `/tmp/vpn-node-tests/JOB_ID/`: до 20 последних заданий, очистка при запуске следующего; после перезагрузки они исчезают. Внутренние результаты автоподбора удаляются после чтения. Одновременно выполняется только один тест, второй получает явную ошибку. Сам тест ничего не выбирает; его использует отдельный конечный подбор `vpn-connection`.

Основа: [sing-box URLTest](https://sing-box.sagernet.org/configuration/outbound/urltest/), [параметры curl](https://curl.se/docs/manpage.html). Наличие успешного TCP handshake само по себе недостаточно для проверки VLESS/REALITY и доступа к сервису.

Старое подключение продолжает работать до применения управляемого профиля. После активации для выбора профиля используется `vpn-profiles`. `vpnctl status check` остаётся доступен для диагностики соединения.

Откат на предыдущую версию выполняется из резервной копии устройства. Выключите VPN, сохраните текущие пользовательские данные и верните прежние CGI, JS/CSS, скрипты, `config.json` и настройки выбора. Переименуйте каталог `profiles`, чтобы после отката прежние скрипты использовали свои данные.
